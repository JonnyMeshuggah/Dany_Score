# Классификация задач по риску

Уровень определяется по **самому рискованному** затронутому пути или действию.
Если сомневаешься между двумя уровнями — бери более высокий.

| Уровень | Что попадает | Минимальный контроль |
|---|---|---|
| **Высокий** | `api/**`, `scripts/**` (доступ к данным), миграции и схема БД, auth, правила доступа `firestore.rules` и `firebase.json`, баланс / начисления / вывод денег, загрузка и сохранение в Firestore или Neon (`onSnapshot`, автосохранение, `set`/`update`), импорт данных, `.claude/**`, `.github/**`, `.githooks/**`, `opencode.json`, новые зависимости, `vercel.json`, env-переменные | Изолированная среда без production-ключей, план + **rollback** до реализации, подтверждение человека, review свежим контекстом (`reviewer`) **и** человеком, security-проверка |
| **Средний** | Новая или изменённая логика в `app.js` (бонусы, боевой пропуск, статистика), изменения в нескольких файлах, новые API-контракты без доступа к данным | План, тесты, review свежим контекстом (`reviewer`), просмотр человеком |
| **Низкий** | `styles.css`, тексты в `faq.html` и UI, документация, локальные переименования | Просмотр diff, `npm run check` |

## Автоматически высокий риск
- Любое изменение, после которого может измениться баланс пользователя или его история.
- Любая операция, которая требует ключа сервисного аккаунта или `DATABASE_URL`.
- Любое изменение `firestore.rules`: после деплоя правил человеком перепроверить
  `node scripts/probe-firestore-rules.mjs` (только тестовый аккаунт).
