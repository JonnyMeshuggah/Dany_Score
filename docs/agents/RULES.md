# Правила работы агентов в Dany_Score

Канонический набор. CLAUDE.md, AGENTS.md и opencode.json только ссылаются сюда — правки вносить здесь.
Основа — командный манифест «AI coding agents: стандарт работы команды».

## Проект в двух словах
- Семейное приложение «Учёба = Деньги» (TakeFive): оценки → рубли, бонусы, боевой пропуск.
- Сейчас: React 18 + Vite (`src/App.jsx`, сборка в `dist/`); Firestore + Firebase Auth; хостинг Vercel.
- Идёт переезд на Neon Postgres — план и статус в `docs/MIGRATION_PLAN.md`.

## Неочевидное (нельзя вывести из кода)
- Firebase подключён compat-скриптами из CDN (глобалы `firebase`, `db`), конфиг приходит из `/api/env`
  inline-скриптом в `index.html`; `initFirebase` в `src/App.jsx` ждёт `window.env`.
- Vercel раздаёт только `dist/`; `.vercelignore` решает, что загружается на сборку. Статика без обработки —
  в `public/`.
- `package.json` без `"type": "module"`: `api/*.js` — CommonJS-функции Vercel. Скрипты Node — `.mjs`.
- Данные пользователя — один документ `users/{uid}`; автосохранение пишет весь `history` целиком.
- Правила наград описаны для пользователя в `public/faq.html` — это продуктовая спецификация.

## Команды
- `npm run check` — lint + поиск секретов + тесты. **Обязателен перед «готово» и перед коммитом.**
- `npm run lint`, `npm test`, `npm run check:secrets` — по отдельности.
- `npm run build` — сборка в `dist/` (без ключей; приложение без `/api/env` не запустится).
- Локального запуска приложения без ключей Firebase нет; UI проверяет человек на Preview-деплое.

## Границы (технически закреплены в `.claude/settings.json` и `.claude/hooks/guard.mjs`)
- Не читать и не изменять `secrets/`, `backups/`, `.env*` (кроме `.env.example`), `*service-account*.json`.
  В `backups/` персональные данные ребёнка.
- Не выполнять `git push`, деплой (`vercel`, `firebase`), `npm publish`, `rm -rf`, `git reset --hard`,
  `--no-verify`. Это делает человек.
- Не ослаблять собственные контроли: изменения в `.claude/`, `.github/`, `.githooks/`, `opencode.json` —
  только по явной просьбе и с подтверждением.

## Процесс
1. Классифицируй риск по `docs/agents/RISK.md` и назови его в начале работы.
2. Средний и высокий риск: исследование → план → подтверждение человека → реализация.
3. Баг: сначала воспроизводящий тест, который падает, затем минимальное исправление.
4. Одна задача — одна ветка; параллельные сессии — только в отдельных git worktree.
5. Небольшие логические коммиты; diff ограничен задачей, без попутного рефакторинга.
6. После двух неудачных попыток исправления — остановись и предложи новую сессию или передать человеку.
7. Готово = выполнен `docs/agents/WORKFLOW.md#definition-of-done`. Без вывода проверок «готово» не говорить.
