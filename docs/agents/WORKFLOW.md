# Рабочий процесс

Подробности к `RULES.md`. Не загружается в каждую сессию — открывается, когда нужно.

## 1. Постановка
Перед реализацией зафиксируй (скилл `/task` в Claude Code):
- **Цель** и пользовательский сценарий («ребёнок добавляет пятёрку → баланс +250»).
- **Область**: какие файлы можно менять; что менять **нельзя**.
- **Риск** по `RISK.md`.
- **Критерии приёмки** — проверяемые: тест, команда, сценарий на Preview.
- **Желаемый размер diff**.

## 2. Исследование
Существующее поведение, инварианты, эталонный паттерн, история спорных мест (`git log -L`, `git blame`).
Для многофайловых задач — read-only (Plan Mode / агент `plan` в OpenCode).

## 3. План
Файлы, контракты, миграции, тесты, порядок внедрения. Для высокого риска — **как откатить**.

## 4. Реализация
Минимальное связное изменение. Без гипотетических абстракций и попутного рефакторинга.
Баг-фикс — по скиллу `/bugfix`: гипотеза → падающий тест → фикс → зелёный тест.

## 5. Самопроверка
`npm run check`. Для UI — сценарий, который человек проверит на Preview (локального запуска без ключей нет).

## 6. Доказательства
Скилл `/done`: выполненные команды и ключевой вывод, изменённые файлы, известные ограничения,
непроверенные гипотезы. Формат совпадает с `.github/pull_request_template.md`.

## 7. Независимое review
Средний и высокий риск: агент `reviewer` (свежий контекст, другая модель) + человек.
Ревьюер ищет только нарушения требований, корректности, безопасности и совместимости.

## 8. Выпуск
Push, PR, деплой и миграции выполняет человек. CI (`.github/workflows/ci.yml`) обязателен для merge.

## Definition of Done
- [ ] Критерии приёмки выполнены.
- [ ] `npm run check` зелёный, вывод показан.
- [ ] Diff просмотрен, ограничен задачей, нет секретов и лишних зависимостей.
- [ ] Для бага есть воспроизводящий тест.
- [ ] Средний/высокий риск: review свежим контекстом пройден, замечания закрыты или явно отклонены.
- [ ] Высокий риск: есть план отката.
- [ ] Ограничения и непроверенное названы явно.

## Когда остановиться
- Две неудачные попытки исправления подряд → новая сессия с переформулированной задачей или человек.
- Задача сменилась → новая сессия (одна сессия — один workstream).
- Нужен доступ, которого нет (ключ, production) → спросить, а не обходить.
